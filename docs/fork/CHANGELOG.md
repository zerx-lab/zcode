- `.github/workflows/sync-upstream.yml`（zcode 上的 fork 新文件）：每日无人值守上游同步——fetch upstream → 种入 `refs/brand/rr-cache` 的 rerere 解法 → rebase `zcode` → `bun run check:ts` 门禁 → `--force-with-lease=zcode` 只推 `zcode`；镜像 `main` 是独立 best-effort 步骤（`continue-on-error`），不阻断核心目标，失败语义单一：run 红 = `zcode` 没动。rebase 循环带进度守卫（`REBASE_HEAD` 不前进即 abort+exit 1，防 hook/提交创建类非冲突失败被 `|| true` 吞掉或无限重试）+ 终态断言（rebase 状态清空且 `merge-base --is-ancestor upstream/main HEAD`），两条失败路径均经 bare-remote 本地复现验证。门禁刻意只跑 `check:ts`：`check:rs` 需 Rust 工具链且编译重，Rust 面由上游 CI 覆盖。前提：fork 默认分支须为 `zcode`（GitHub `schedule` 只读默认分支上的 workflow）。配套 `brand/sync.sh` 增加 rerere 启用与解法发布：全绿后把 `.git/rr-cache` 用独立 `GIT_INDEX_FILE`/`GIT_WORK_TREE` 写成 tree/commit 推到 `refs/brand/rr-cache`（选 ref 而非 actions/cache：受控写入、不被 7 天缓存淘汰、不污染分支列表）——同一冲突人工只解一次，之后 CI 自动重放。
- 文件式 slash command 支持 opencode 风格的 `agent` / `model` / `subtask` frontmatter（对齐 https://opencode.ai/docs/commands/ 的 command→agent 语义），可用配置好的 model role 定向执行：**subagent 模式**（写 `agent:`，或 `subtask: true`）由代码直接下单——命令展开后 `agent` / `task` 参数已完全确定，`extensibility/command-subagent-dispatch.ts` 自己发出 `task` 调用，并把 assistant(toolCall) → `tool_execution_start/update/end` → toolResult 的事件序列按 `executeToolCalls` 原样补齐（`emitExternalEvent` 的 `message_end` 分支负责入 state + 落盘 + 渲染），随后以 `agent.continue()` 回到 loop：整轮只剩一次模型调用，而且它是转述而不是下单。由此命令体逐字送达 subagent（不再依赖提示词里的 "VERBATIM" 祈使句），flat wire shape 由代码选定（不再让模型在 `{task}` 与 `{context, tasks[]}` 间猜），frontmatter 可直通 `name` / `outputSchema` / `schemaMode` / `isolated` / `effort` 这些以前无法表达的 per-spawn 字段。`task` 工具不可用时直接拒绝该命令并报错——`subtask` 要的是委派，静默退化成主 agent 亲自干是反语义。命令级 `model:` 仍走 `task.agentModelOverrides` 运行时层（wire schema 不带 model，这是唯一通道），但持有窗口从「一整个模型 turn」收缩到包住 `execute` 的 try/finally。中断可达：新增的 `registerPreModelAbort()` 把这段 loop 尚未接管的执行接进 `session.abort()`。**当前会话模式**（只写 `model:`，或 `subtask: false`）用 `setModelTemporary(..., { ephemeral: true })` 单轮换模型执行，`agent_end`（含 abort/error）还原原模型与 thinking 档。选择器推荐角色别名（`@advisor`），改绑角色即全部命令跟随。流式中触发时降级为纯文本展开并告警（一次 dispatch 独占整轮，中途插入会劫持在跑的 loop）。实现在新文件 `extensibility/command-dispatch.ts`（解析 + 路由）与 `extensibility/command-subagent-dispatch.ts`（提交 + 执行 + 续跑）；上游接线为 `slash-commands.ts` 挂 `dispatch` 字段 + `agent-session.ts` 约 20 行（prompt 路径接 outcome、`#promptWithMessage` 的 `subagentDispatch` 分支、`registerPreModelAbort` 与 `abort()` 各一行），TUI/ACP/RPC 三模式共用该入口。测试 `test/command-dispatch.test.ts`（27 例，含 `@role` 别名经真实 resolver 的路径与双向还原）与 `test/command-subagent-dispatch.test.ts`（端到端：mock provider 只被调用一次，且那次的 context 已是 `[user, assistant(toolCall), toolResult]`）。刻意不抄 opencode 的已知坑：其 subtask 路径下 `agent.model` 反超 `cmd.model`（`tool/task.ts:181`，与非 subtask 路径优先级相反），本实现统一命令级 `model:` 最高优先。
