# 界面多语言（i18n）

fork 侧新增能力：设置面板、欢迎页与内置提示支持简体中文，用户在**设置 → 外观 → 显示 → 界面语言**里切换，即时生效。

设计目标与本 fork 的其它改动一致：**翻译内容 100% 落在上游不存在的新目录，上游文件只保留取词那一行**（见 `docs/fork/sync-strategy.md`）。

## 分层

```
packages/coding-agent/src/i18n/          ← 全部新文件，rebase 永不冲突
  constants.ts      零依赖：设置 path / 候选值 / 选项元数据
  types.ts          字典类型
  locale.ts         locale 解析 + 缓存
  index.ts          取词 API：t / tf / tTab / tGroup / tTip / localizeSettingDefs / localizeSlashCommands
  locales/zh-CN/
    index.ts        语言包
    settings/       333 条设置项译文，按设置面板 tab 分 10 个文件
    commands/       70 条内置 slash 命令 + 106 个子命令描述，分 3 个文件
    tabs.ts         tab 标题 + 分组标题
    chrome.ts       界面固定文案
    tips.ts         欢迎页 tips
```

## 键的选择：两套，各有理由

|字典|键|上游改动时的行为|
|---|---|---|
|`settings`|**setting path**（`theme.dark`）|上游改英文文案 → 中文照常显示。path 消失 → 测试报「死键」|
|`commands`|**命令名**（`quit`、`security`）|同上。命令名本身是用户输入的 token，天然稳定|
|`tabs` / `groups`|**英文 tab id / 组名**|组名是排序键，见下|
|`chrome` / `tips`|**英文原文**|上游改原文 → 静默回退英文，绝不显示对不上的旧译文|

设置项用 path 是因为它是稳定标识；chrome / tips 没有标识符，只能用原文，代价是上游改一个字就 miss —— 但 miss 的后果是回退英文，不是错译，可接受。

## 五个非显然的约束（改动前必读）

1. **`group` 不能翻译。** `getSettingsForTab` 用 `TAB_GROUPS` 的英文组名 `indexOf` 排序，译过的组名全部落空 → 分组顺序退化。`localizeSettingDefs` 因此刻意跳过 `group`，改在渲染点（heading 行、sidebar 宽度）经 `tGroup()` 取词。
2. **每个按 locale 变化的缓存都要把 locale 纳入键。** 已处理三处：`settings-defs` 的 `cachedDefs`、`settings-selector` 的 `cachedSidebarWidth`、`welcome` 的 `#cachedLines`。welcome 尤其容易漏 —— 语言切换发生在设置面板里，没有任何代码会去 `invalidate()` 欢迎页。
3. **Settings 未初始化时必须返回 `en`，不能探测宿主 locale。** 早期启动、SDK 嵌入与单测都会走到这条路径；若在这里落回 `auto` → 宿主 locale，中文机器上断言英文文案的上游测试会随文件执行顺序时红时绿。`locale.ts` 的 `resolveLocale()` 对此有显式注释。
4. **语言变更回调里必须先 `refreshLocale()` 再重建。** `SettingsSelectorComponent` 的顺序是「`settings.set` → `callbacks.onChange` → `#relocalize()`」，所以 `onChange` 触发时 locale 缓存仍是旧值。`selector-controller.handleSettingChange` 的语言分支因此自己先刷新，否则重建出来的命令表是**上一个语言**。这条由 `localization.test.ts` 的「only rebuilds … after the locale cache is refreshed」钉住 —— 它显式断言不刷新时拿到的仍是英文。
5. **静态 `description` 不是命令列表实际显示的东西。** `packages/tui` 的 `getAutocompleteCommandDescription` 优先取 `getAutocompleteDescription()`，只有它缺席才回落静态字段。23 条命令带 `getTuiAutocompleteDescription`（`/model`、`/loop`、`/tools`、`/context`…），只翻静态 description 的话补全列表全是英文。这些分支逐个走 `t()` / `tf()`，`{0}` 里留运行时值（模型 id、百分比、计数）不译。`/loop` 的限额文本来自 `modes/loop-limit.ts` 的 formatter，也一并取词 —— 否则会出现「循环模式：开（3 of 10 iterations remaining）」这种半中半英。**新增带动态描述的命令时，覆盖率测试不会提醒你**（它只看静态字典），要靠 `localization.test.ts` 的状态矩阵用例补一行断言。

`matchLocaleTag` 的取舍：同时吃 POSIX（`zh_CN.UTF-8`）与 BCP-47（`zh-Hans-CN`）。**两个正则都不能用 `\b`** —— `_` 是单词字符：`zh_CN` 会漏判成非中文，而繁体判别里 `zh_Hant_TW` 会漏判成简体（同一个标签写成 `zh-Hant-TW` 却命中，行为按分隔符分裂）。子标签边界一律写 `(?![a-z0-9])` 或显式 `[-_.]`。明确的繁体标签（`zh-Hant` / `zh_TW` / `zh_HK` / `zh_MO`，含下划线与大写变体）回退英文，没有繁体语言包时不拿简体冒充。

`auto` 的解析顺序沿用 POSIX 惯例 `LC_ALL > LC_MESSAGES > LANG > LANGUAGE`，四个都没有才用 ICU 的系统 locale。前三个各自是**单个** locale，`LANGUAGE` 是 GNU gettext 的**冒号分隔优先列表**，必须逐项挑第一个有语言包的候选 —— `de_DE:zh_CN` 当成单标签就会丢掉可用的第二候选。这也是 `matchSupportedTag` 要把「明确英文」（`en_US:zh_CN` → 英文）与「没有语言包」（`zh_Hant_TW:zh_CN` → 继续找 → 简体）区分成 `"en"` / `null` 的原因。测试必须把这**四个变量一起**清掉再设，只控制 `LANG` 会被 CI 预设的 `LC_ALL` 推翻（`localization.test.ts` 的 `withLocaleEnv` 就是干这个的）。

## 同步后的维护

`packages/coding-agent/test/i18n/localization.test.ts` 是维护信号：

- 上游**新增**设置项 / 枚举选项 / slash 命令 / 子命令 / tip → 覆盖率用例变红，补对应译文即可。
- 上游**删除**设置项或命令 → 「死键」用例变红，删掉残留译文。
- 上游改 chrome 原文 → 不会红（静默回退英文）。这类漂移靠同步时人工过 `settings-selector.ts` / `welcome.ts` 的冲突块发现 —— 冲突块本身就落在取词那一行上。

## 加一门语言

1. 复制 `locales/zh-CN/` 为新目录，翻译内容。
2. `types.ts` 的 `LocaleId` 加成员，`constants.ts` 的 `LANGUAGE_SETTING_VALUES` / `LANGUAGE_SETTING_OPTIONS` 各加一条。
3. `locale.ts` 的 `BUNDLES` 注册，`matchLocaleTag` 加前缀判断。

上游文件一行都不用动。

## 未覆盖的表面

本次覆盖设置面板（全部）、欢迎页、`tips.txt`、内置 slash 命令与子命令描述。**未覆盖**：工具渲染器输出、MCP/SSH 控制器的错误提示、setup wizard、`/help` 之外的命令执行结果文案。这些分布在数百个文件里，逐处 `t()` 会把冲突面推到无法维护的量级；真要做，应先在各自的渲染出口找到类似 `settings-defs` / `builtin-registry` 那样的瓶颈点，而不是逐条包裹。
