用 `task` 派一个 `index-keeper` 子 agent 做 `AGENTS.md` 对账。传给它的 context 必须包含：

- 仓库根绝对路径；
- 本次会话里发生过的、可能产生新坐标的改动（新增/移动/删除了哪些路径、改了哪些导出符号）；
- 用户额外指定的关注点（见下方）。

它返回后由你验收，不要照抄它的结论：

1. 它删掉的每个条目，抽查一到两条，确认路径确实不存在且该行没有 `(planned)` 标记；
2. 它新增的每个坐标，确认路径存在且职责描述与代码一致；
3. 确认 `AGENTS.md` 仍 ≤120 行，且它搬进 `.omp/rules/` 的内容**已从索引删除**（不是复制过去）；
4. 确认它跑过 `bun .omp/checks/index-guard.check.ts` 且最终无违规。

任何一条不达标，把具体问题回给同一个 agent 让它修，不要自己动手补 —— 保持单一维护者。

验收通过后向用户报告：删了什么、加了什么、搬了什么、检查器最终输出。没有改动就说没有改动。

本次对账的关注点：$ARGUMENTS
