# ZCode 红线

- 未经用户明确要求，绝不 `git commit` / `git push` / 建 PR / 建 issue / 在 GitHub 上发表任何评论。
- 绝不手改生成物。改生成器源头，见 `rule://zcode-architecture`。
- 绝不用占位实现冒充完成：stub、mock、`todo!()`、静默 fallback，以及 "MVP / v1 / 后续补" 式标签一律不算交付。
  做不到就直说缺哪个前置条件，并把能做完的部分做完。
- 说 "已验证" 之前必须真的跑过对应路径，并写出跑了什么、看到什么。跑不了就说跑不了，不要用推测替代。
- 库代码里的 `unwrap` / `expect` / `panic!` 与 `as` 数值转换按缺陷处理；确属例外时同行写出理由。
- 新增约定前先搜现有实现。与既有约定并行的第二套写法一律拒绝：先迁移调用点，再删旧路径。
- 改动导出符号前必须用 `lsp references` 核实全部调用点，不靠猜、不靠文本搜索。
- 面向用户的散文与最终回答用简体中文；代码、命令、标识符保持英文。
