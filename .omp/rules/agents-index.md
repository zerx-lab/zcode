# AGENTS.md 索引规范

`AGENTS.md` 是**索引**：让 agent 在陌生会话里快速定位，而不是让 agent 读完就懂全部。
它在每个会话开场被完整注入一次，所以每一行都在花预算。

## 为什么必须短

指令数量上升时，模型对**全部**指令的遵循率下降（不是只丢尾部）；超预算时常见的截断策略会砍掉中段，
恰好是细则所在的位置。结论：长索引不是"信息更多"，而是"约束更弱"。

因此：

- 全文 ≤ **120 行**，单节 ≤ 25 行；
- 全局 bullet 级硬规则控制在 40 条以内；
- 超出就拆进 `.omp/rules/`，靠 `rule://<name>` 按需加载 —— 那些内容只在系统提示里占一行 name + description。

## 分层归属

| 内容性质                         | 归属                                       |
| -------------------------------- | ------------------------------------------ |
| 坐标：路径 → 职责、入口符号      | `AGENTS.md` 代码地图                        |
| 命令：闸门与聚焦验证             | `AGENTS.md` 命令表（唯一事实来源）          |
| 行为红线，长会话也不能忘         | `.omp/RULES.md`（always-apply）             |
| 领域细则，按需读                 | `.omp/rules/<domain>.md`（带 description）  |
| 写某类代码时必须当场看到的替代方案 | `.omp/rules/*.md` + `condition`（TTSR，命中即注入） |
| 跨会话的决策、教训、个人偏好      | 长期记忆（`retain` / `recall` / `reflect`），不进 git |

**长期记忆与索引的边界**：`AGENTS.md` 存**可被机器校验的坐标**（路径 → 职责、命令）；长期记忆存
**决策、踩过的坑、偏好**。不要把路径坐标只 `retain` 而不写索引 —— 记忆是启发式背景，不是项目真相，
与代码或 `AGENTS.md` 冲突时以后者为准。会话压缩只改写会话历史，`AGENTS.md`、`RULES.md`、rulebook
列表每轮重新组装，所以压缩后仍应打开 `AGENTS.md` / `rule://` 核对，不能只信摘要与 `<memories>`。

**同一条约束只允许存在一份。** 这不只是洁癖：always-apply 规则（`RULES.md`）的内容若已出现在
**context file**（即 `AGENTS.md`）里，会被去重逻辑**静默跳过注入** —— 在 `AGENTS.md` 里复述一遍
`RULES.md` 的条款，等于让那一条彻底失效。按需读取的 `.omp/rules/*.md` 不参与这个去重，
但同一约束散在多份 rule 里仍会导致改一处漏一处。

## 写入条件

三条同时满足才写进 `AGENTS.md`：

1. 跨会话仍然成立（不是本次任务状态）；
2. 无法由工具强制（clippy / rustfmt / 测试 / CI 能管的，交给它们）；
3. 能用一行说清（超过 3 行 → 进 `.omp/rules/`）。

典型可写：路径 → 职责、决策及其**理由**、已经踩过两次的坑。
典型不可写：粘贴的代码块、尚未验证的猜测、"未来可能要做"的设想、外部库用法教程。

## 删除条件

满足任一即删该条目，**不需要征询用户**：

- 反引号路径已不存在，且该行没有 `(planned)` 标记；
- 与代码或 `.omp/rules/` 冲突 —— 代码是事实来源；
- 所列命令跑不通；
- 条目描述的决策已被替换。

删除优先于改写。改写的成本是"读者要判断新旧"，删除的成本是零。

## `(planned)` 标记

引用**尚未落盘**的路径时，同一行必须包含 `(planned)` 字面量：

```markdown
`crates/tui/` (planned) — 差分渲染终端 UI
```

自动检查靠这个标记区分"设计意图"与"过时残留"。路径真正落盘后**删掉标记**，
否则它会永久豁免检查，等于关掉了保护。

## 新鲜度锚

文件末尾一行：

```markdown
<!-- index-verified: <commit-sha> <YYYY-MM-DD> -->
```

`git init` 之前写 `none`。对账通过后把它更新到当时的 HEAD 与日期。
检查器用它判断索引落后了多少提交（阈值：30 个提交或 14 天）。

## 自动检查

守卫做**四项确定性检测**：行数上限、反引号路径是否存在（`(planned)` 行豁免）、
**顶层目录是否已有坐标**、锚是否新鲜。

第三项是反向检测：索引里的路径都还在，但仓库长出了索引不知道的结构。判据是
**顶层目录名是否作为反引号路径 token 出现在索引里** —— 必须按 token 精确比对，
不能用全文子串（那样 `test/` 会被命令表里的 `cargo test` 命中，检测直接失效）。
工具/VCS 私有目录与构建产物在白名单里；确实不该进索引的目录用显式豁免：

```markdown
<!-- index-ignore: scratch, sandbox -->
```

豁免会落盘、可 review。**不要靠让检测保持红色来表达"我看过了"。**

触发点：

| 时机 | 行为 |
| --- | --- |
| `write` 提交超长 `AGENTS.md` | **直接拒绝**（`tool_call` 硬闸门） |
| `write` / `edit` / `bash` 执行后 | 重跑检测，违规则把报告追加到工具结果（不改成失败） |
| 会话开场 | 静默检测，仅违规才提示 |
| **会话收尾前** | 违规则**强制续跑一轮做对账**，每会话只触发一次 |
| 人工 / CI | `bun .omp/checks/index-guard.check.ts`，违规退出码 1 |

收尾对账是唯一不依赖人工触发的环节：不必有人记得跑 `/sync-index`，索引不同步就不会安静地结束会话。
但**改写仍由 agent 做** —— 哪条该删、哪个目录该有坐标是语义判断，机器只能定位不能决定。

守卫抓不到的是**语义过时**：路径还在、目录有坐标，但职责描述已经不对、决策已被推翻。
这类只能靠读代码发现 —— 这是 `/sync-index` 派 `index-keeper` 逐条核对的理由。
