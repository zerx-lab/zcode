# Rust 测试规范

## 放置位置

- 单元测试放在被测模块内的 `#[cfg(test)] mod tests`。
- 跨模块的集成测试放在 crate 的 `tests/` 目录。

## 契约优先

- 每个测试必须保护一个**外部可观察的契约**：行为、输出形态、状态转换、错误映射，或易回归的解析边界。说不出该契约就不写这个测试。
- 优先契约级测试，而非实现细节测试——除非其他组件确实依赖这些细节，否则不断言内部辅助函数的连接方式、字段赋值、`Arc::ptr_eq` 式实例身份、偶然排序。
- 若集成测试已证明某行为，删除用 mock 重述同一行为的更窄单元测试，不要跨抽象层重复覆盖。
- 微小、低风险的改动不加测试，除非该测试保护真实契约或修复易回归的边缘情况。

## 禁止的断言写法

- 禁止占位/恒真断言：`assert!(true)`、仅 `is_ok()`、非空字符串检查、长度增加检查、不含语义断言的“XX 存在”检查。
- **禁止对源码文本做 grep 式测试**：读取实现文件（`.rs`/构建脚本）并对其*文本*断言，例如 `assert!(src.contains("some_call()"))`、正则匹配 `use ...`、`!src.contains("old_name")`。理由：无害重构（换行、重命名、导入重排）会让它变红；真实行为损坏时它可能仍是绿的——它测的是代码“长什么样”，不是“做了什么”。
  - 结构性不变量（不得依赖某 crate、禁止循环依赖）改用 `cargo-deny`、feature 门控或 clippy lint 强制执行。
  - 例外：读取由代码自身**生成**的产物（apply-patch 结果、生成的 fixture、临时输出文件）并断言其内容，测的是行为，允许。
- 仅当下游代码确实解析/依赖精确字节时才断言精确字符串、顺序、格式；否则断言语义内容。

## 并行安全

`cargo test`/`cargo nextest run` 默认多线程并行，全套测试必须并行安全：

- 禁止 `std::env::set_var`/`remove_var`——把配置作为函数参数或结构体字段注入。
- 禁止写固定路径的临时文件——用 `tempfile::tempdir()`。
- 禁止依赖当前工作目录。
- 确实必须串行时用 `#[serial_test::serial]`，但这是最后手段，不是默认选项。

## Mock 策略

- 禁止全局替换式 mock（进程级单例覆盖、`static mut` 注入、猴子补丁式全局注册表改写）——会跨测试泄漏状态。
- 用 trait 抽象 + 依赖注入替换协作者：为被依赖行为定义 trait，测试传入 fake 实现。
- 网络交互用本地测试服务器（`axum`/`wiremock`），不要拦截全局 HTTP client。

## 错误路径

- 触发真实失败路径并断言对外契约（错误变体、`Display` 输出中面向用户的部分），不要直接构造错误值或检查内部元数据。

## 编译期保证

- 用类型系统本身表达不变量；需要断言“某代码不应通过编译”时用 `trybuild`/`compile_fail` 文档测试，不要用运行时占位测试模拟。

## unwrap/expect 例外

- 测试代码允许 `unwrap()`/`expect()`（`clippy.toml`：`allow-unwrap-in-tests = true`、`allow-expect-in-tests = true`），不受 `rule://rust-quality` 的库代码限制。

## 本地验证

- 聚焦验证与全套闸门命令以 `AGENTS.md` 的命令表为唯一事实来源，不在本文件复制一份。
- **doctest 不进 nextest**（nextest 不执行 doctest）：跑完 nextest 后必须另跑索引命令表里的 doctest 那一条，否则文档示例根本没被验证。
